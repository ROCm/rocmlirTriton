patch-buffer-atomics.patch
  Enables buffer atomic RMW across all AMD GPU families in
  TargetFeatures::supportsBufferAtomicRMW (gfx906/gfx908/gfx90a/gfx942/gfx950,
  gfx101x/gfx103x/gfx11/gfx12, gfx1250). On older families BUFFER_ATOMIC_*
  silently drops writes against fine-grained pinned host memory, but
  rocmlirTriton never targets such allocations so this is safe.
  Integer RMW works universally; the per-family FP restrictions for
  BUFFER_ATOMIC_ADD_{F32,F64}/PK_ADD_{F16,BF16} are encoded in
  supportsBufferAtomicFadd (e.g. gfx906/gfx101x/gfx103x have no FP buffer
  atomic add; gfx11 only F32; gfx942 no PK_ADD_BF16; gfx12 no F64).
  Upstreaming was attempted in https://github.com/triton-lang/triton/pull/10408
  but it was rejected.

patch10498.patch
  Extends patch10450's soffset-split safety check to peel sign-preserving
  transparent wrappers (splat/broadcast/expand_dims/reshape/convert_layout)
  before trusting the integer-range lattice, so an offset of the form
  convert_layout(add(base, <negative>)) is no longer wrongly annotated
  split-safe. Applies on top of patch10450. Mirrors upstream Triton PR
  https://github.com/triton-lang/triton/pull/10498 exactly.

patch10585.patch
  Fixes a case where the block ping pong schedule was wrongly being applied
  in situations where it was not safe to do so because of non-uniform masks.
  
patch-wmma-preserve-discardable-attrs.patch
  Lets rocmlirTriton choose the WMMA result transposition downstream instead
  of inside Triton.

  rocmlirTriton computes a `rock.o_transposed` discardable attribute at the
  rock level (rock-add-triton-metadata, run right after rock-lower-stores,
  using the store destination's getMaxVectorization), carries it onto the
  lowered tt.dot/tt.dot_scaled (RockToTTIR), and finally consumes it after
  accelerate-matmul (rock-set-matmul-output-transpose) to set the WMMA
  isTransposed flag so the epilogue store coalesces.

  This patch is the small piece that has to live inside Triton: it makes
  AccelerateAMDMatmul copy the discardable attributes from the original dot
  onto every freshly-created accelerator dot (MFMA / WMMA / scaled / v_dot /
  FMA paths) so downstream metadata such as `rock.o_transposed` survives the
  rewrite. It adds no Triton-side decision logic; the orientation is chosen
  by the downstream rock pass.

patch-float-atomic-minmax-lowering.patch
  Fixes Triton atomic max/min lowering for floating-point element types. The
  shared matchAtomicOp helper now receives the value type and maps floating
  MAX/MIN operations to LLVM `fmax` / `fmin` rather than integer max/min; the
  AMD intra-wave reduction path handles those new floating atomic binops.

patch-preserve-arith-bitcast-lowering.patch
  Keeps `arith.bitcast` legal through Triton's Triton-to-TritonGPU and
  TritonGPU-to-LLVM conversion pipeline by adding the corresponding generic
  conversion and LLVM lowering patterns.

patch-skip-subbyte-reduce-data-duplication.patch
  Prevents ReduceDataDuplication from materializing sub-byte tensors through
  local memory. Triton's convert-layout lowering already widens these transfers
  to i8 and truncates back to the logical element type, so introducing local
  memory here is incorrect for sub-byte element types.

patch10497.patch
  Adds the RDNA FMA-dot layout rebalancing logic in AccelerateAMDMatmul, plus
  coverage for f32 FMA dots on RDNA. When WMMA cannot handle the dot, the FMA
  path rewrites imbalanced blocked layouts into a more balanced layout to
  reduce LDS read volume, then converts back to the original result layout.

patch10563.patch
  Extends InThreadTranspose coverage and logic for the FMA dot path on RDNA.
  The pass now recognizes when FMA dot operands benefit from an in-thread
  transpose and avoids applying the transform when the operand-major layout is
  already the orientation the FMA dot wants in LDS.

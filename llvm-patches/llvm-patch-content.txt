llvm-patches/ -- downstream LLVM cherry-picks
=============================================

This directory holds patches against the LLVM checkout that Triton pins
(external/triton/llvm-project).

----------------------------------------------------------------------
patch167347.patch
----------------------------------------------------------------------
- Upstream PR : https://github.com/llvm/llvm-project/pull/167347 (open)
- File Fixed  : llvm/lib/Target/AMDGPU/AMDGPURewriteAGPRCopyMFMA.cpp
               (+ new header AMDGPURewriteAGPRCopyMFMA.h)

Adds a joint-dominance safety check to the AGPR-copy-MFMA spill-slot
elimination. Before eliminating the spills of a reassigned VGPR, the pass
now requires that every reachable reload of a stack slot is jointly
dominated by a store to the same slot (helper
AMDGPU::checkAGPRCopyMFMAJointDominance, gated on a new
MachineDominatorTree analysis dependency). Without it the pass can emit
MIR where a vreg use is not dominated by its def, which the
MachineVerifier rejects ("Virtual register defs don't dominate all uses")
and the AMDGPU backend aborts via report_fatal_error.

Symptom without the patch: rocmlir-driver -c aborts during
TritonToHsacoPass (LLVM IR to AMDGCN) on f32 attention for gfx950 with
attn-bias + split-KV > 1 at a tile-heavy perfConfig. Only the backend fix
is carried; the upstream PR's unit-test additions are intentionally
skipped.
